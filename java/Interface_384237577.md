# 인터페이스의 역할 및 정의
- 인터페이스는 객체의 상태가 아닌 동작을 명시
- 개발코드와 객체가 서로 통신하는 접점 역할
- 인터페이스를 통해 사용하는 객체를 변경 가능
- interface 를 선언하여 클래스 정의
- ⚠️ 만일 클래스가 인터페이스의 메서드 중 일부만 구현한다면 해당 클래스를 반드시 abstract로 선언해야 함.

- java8 이후 default 메소드와 정적 메소드 선언 가능
```java
  interace 인터페이스명 {
    //상수
    public int MAX_VOLUME = 10;
    //추상 메소드
    public void turnOn();
    public void turnOff();
    // default 메소드
    default void setSound(boolean onOff) {
      ...
    }
    // 정적 메소드
    static void changeBattery() {
      ...
    }
  }
```

- 상수 필드
    - 인터페이스에 정의한 변수는 자동으로 public static final로 선언
    - 인터페이스 상수는 static{} 블록으로 초기화할 수 없기 때문에 선언시 초기값 지정

- 추상 메소드
    - 인터페이스를 통해 호출된 메소드는 객체에서 실행됨
    - 인터페이스를 상속받은 클래스에서 메소드 구현
    - public abstract 를 생략해도 컴파일 과정에 붙음

- default 메소드(java 8부터 추가됨)
    - 추상 메소드와 달리 구현 소스를 갖는 메소드
    - 인터페이스 메소드를 직접 호출 가능하지 않음
    - 구현 객체가 있어서 실행 가능(구현 객체에 정의되지 않아도 됨)
    - 모든 구현 객체가 가지고 있는 기본 메소드. 재정의 가능

- 정적 메소드(java 8부터 추가됨)
    - 클래스의 정적 메소드와 동일한 기능 수행
    - 인터페이스로 바로 호출 가능

# 인터페이스 구현

## 구현 클래스
- interface를 implements 하여 클래스 구현
- interface를 implements 하였지만 메소드를 구현하지 않으면 자동으로 abstract 클래스가 됨
```java
  public abstract class 클래스 implements RemoteControl {

  }
```

## 익명 구현 객체
- 일회성의 구현 객체를 만들기 위해 소스 파일 및 클래스 선언하는 것을 대체하는 방법

- 익명 구현 객체 선언 방법
```java
  RemoteControl rc = new RemoteControl() {  // 인터페이스 변수 = new 인터페이스(){}
    public void turnOn(){...}
    public void turnOff(){...}
    public void setVolume(int volume){...}
  }
```

# 타입변환과 다형성

## 필드의 다형성
- 클래스 필드를 선언할 때 인터페이스로 선언하면 여러 객체를 할당할 수 있으므로 필드의 다형성을 가짐

  - 예제
```java
    // interface 정의
    public interface Tire {
      public void roll();
    }

    // 인터페이스를 구현한 클래스
    public class HankookTire implements Tire {
      @Override
      public void roll() {
        System.out.println("한국 타이어가 굴러갑니다.");
      }
    }

    public class KummhjoTire implements Tire {
      @Override
      public void roll() {
        System.out.println("금호 타이어가 굴러갑니다.");
      }
    }

    // 필드를 인터페이스로 구현한 클래스
    public class Car {
      Tire frontleftTire = new HankookTire();
      Tire frontRightTire = new HankookTire();
      Tire backLeftTire = new HankookTire();
      Tire backRightTire = new HankookTire();

      void run() {
        frontLeftTire.roll();
        frontRightTire.roll();
        backLeftTire.roll();
        backRightTire.roll();
      }
    }

    // 필드 다형성 테스트
    public class CarExample() {
      public static void main(String[] args) {
        Car myCar = new Car();

        mycar.run();

        myCar.frontLeftTire = new KumhoTire();
        myCar.frontRightTire = new KumhoTire();

        myCar.run();
      }
    }
```

- 인터페이스 배열로 구현 객체 관리
  - 앞의 예제에서 4개의 Tire 필드를 인터페이스 배열로 관리
```java
    // 다형성 필드를 인터페이스 배열로 변경
    public class Car {
      Tire[] tires = {
        new HankookTire(),
        new HankookTire(),
        new HankookTire(),
        new HankookTire()
      } ;

      void run() {
        for(Tire tire : tires) {
          tire.roll();
        }
      }
    }
```

- 필드 다형성 테스트 예제
```java
    // 필드 다형성 테스트
    public class CarExample() {
      public static void main(String[] args) {
        Car myCar = new Car();

        mycar.run();

        myCar.tires[0] = new KumhoTire();
        myCar.tires[1] = new KumhoTire();

        myCar.run();
      }
    }
```

## 매개변수의 다형성

- 메소드에서 사용하는 매개 변수를 인터페이스를 상속받은 객체로 할당할 경우, 필요에 따라 매개변수를 다른 객체로 변경 가능 : 실행결과가 다양하게 나옴
```java
  public void useRemoteControl(RemoteControl rc){...}
```

- 매개변수를 인터페이스 타입으로 선언, 호출 할 때에는 구현 객체 대입
```java
  public interface Vehicle {
    public void run();
  }
```

- 매개변수를 인터페이스로 갖는 클래스 정의
```java
    public class Driver {
      public void drive(Vehicle vehicle) {
        vehicle.run();
      }
    }
```

- 인터페이스 구현 클래스
```java
    public class Bus implements Vehicle {
      @Override
      public void run() {
        System.out.println("버스가 달립니다.");
      }
    }

    public class Taxi implements Vehicle {
      @Override
      public void run() {
        System.out.println("택시가 달립니다.");
      }
    }
```

- 매개변수 다형성 테스트 예제
```java
    public class DriverExample {
      public static void main(String[] args) {
        Driver driver = new Driver();

        Bus bus = new Bus();
        Taxi taxi = new Taxi();

        driver.drive(bus);  //자동변환
        driver.drive(taxi);
      }
    }
```

## 강제 타입 변환(Casting)
- 구현 객체가 인터페이스 타입으로 자동 변환하면 인터페이스의 정의된 메소드만 사용 가능
  - 예로 인터페이스 정의 메소드 3개, 구현 객체 메소드 5개일 때, 자동 변환되면 메소드 3개만 사용가능
  - 경우에 따라 인터페이스에 없는 구현 객체에만 메소드 호출이 필요한 경우, 강제 타입 변환하여 호출
  - 강제 타입 변환 예제
```java
    public interface Vehicle {
      public void run();
    }

    public class Bus implements Vehicle {
      @Override
      public void run() {
        System.out.println("버스가 달립니다.");
      }

      public void checkFare() {
        System.out.println("승차요금을 체크합니다.");
      }
    }

    public class VehicleExample {
      public static void main(String[] args) {
        Vehicle vehicle = new Bus();
        vehicle.run();
        // vehicle.checkFare();  실행 안됨

        Bus bus = (Bus)vehicle;  // 강제타입 변환
        bus.run();
        bus.checkFare();
      }
    }
```

## 객체유형확인
- 타입 변환을 하기 전 어떤 객체 유형인지 확인하기 위해 instanceof 으로 객체 타입을 확인
```java
  public class Driver {
    public void drive(Vehicle vehicle) {
      if(vehicle instanceof Bus) {  // Bus가 아닌 다른 객체인 경우  오류 발생
        Bus bus = (Bus)Vehicle;
        bus.checkFare();
      }
      vehicle.run();
    }
  }
```

# 디폴트 메소드와 인터페이스 확장

## 디폴트 메소드의 필요성
- 기존 인터페이스를 확장해서 새로운 기능을 추가
- 기존 인터페이스의 이름과 추상 메소드 변경 없이 메소드 추가가 가능
  - 인터페이스에 새로운 추상 메소드 추가시 구현 객체에 모든 구현 메소드를 추가해야 함.
  - 디폴트 메소드 추가시 기존 구현 객체에 영향을 미치지 않음

## 디폴트 메소드가 있는 인터페이스 상속
- 부모 인터페이스 정의
```java
  public interface ParentInterface {
    public void method1();
    public default void method2(); // default 메소드
  }
```

### 디폴트 메소드를 상속
- 단순히 상속 받는 예제
```java
  public interface ChildInterface1 extends ParentInterface {
    public void method3();
  }
```

- 구현 객체
```java
  ChildInterface1 ci1 = new ChildInterface1() {
    @Override
    public void method1(){}
    public void method3(){}
  };

  ci1.method1();
  ci1.method2();  // parentInterface method2() 호출
  ci1.method3();
```

### 디폴트 메소드를 재정의해서 실행 내용 변경
- 재정의한 인터페이스
```java
  public interface ChildInterface2 extends ParentInterface {
    @Override
    public default void method2() {}  // 재정의
    public void method3();
  }
```

- 구현객체
```java
  ChildInterface2 ci2 = new ChildInterface2() {
    @Override
    public void method1(){}
    @Override
    public void method3(){}
  };

  ci1.method1();
  ci1.method2();  // ChildInterface2 method2() 호출
  ci1.method3();
```

### 디폴트 메소드를 추상 메소드로 재선언
- 재정의한 인터페이스
```java
  public interface ChildInterface3 extends ParentInterface {
    @Override
    public default void method2(); // 추상 메소드 재선언
    public void method3();
  }
```

- 구현객체
```java
  ChildInterface3 ci3 = new ChildInterface3() {
    @Override
    public void method1(){}
    @Override
    public void method2(){}
    @Override
    public void method3(){}
  };

  ci1.method1();
  ci1.method2();  // ChildInterface3 구현 객체의 method2() 호출
  ci1.method3();
```

### 동일한 디폴트 메소드를 가진 두 인터페이스 상속(디폴트 메소드 충돌 해결)
- 실제 사용할 디폴트 메소드를 가진 두 인터페이스를 구현
	```java 
	public interface Person {
		String getName();
		default int getId() { return 0;}
	}
	
	public interface Identified {
		default int getId() { return Math.abs(hashCode());}
	}
	
	// 상속 구현 클래스
	public class Employee implements Person, Identified {
		// super의 default 메서드 중 하나의 메서드로 위임
		public int getid() { return Identified.super.getId();}
	}
	```

## 인터페이스 예
### Comparable interface
- 클래스가 자신이 갖고 있는 개체를 정렬
	```java
	public interface Comparable<T> {
		int compareTo(T other);
	}
	```
- 예제
	```java
	public class Employee implements Comparable<Employee> {
		public int compareTo(Employee other) {
			return getId() - other.getId();
		}
	}
	```

## 람다 표현식
- 한번이든 여러 번 이든 나중에 실행할 수 있게 전달하는 코드 블록(의미가?)
- 자바에는 함수 타입이 없다. 대신 함수를 객체로 표현-> 특정 인터페이스를 구현하는 클래스 인스턴스로 표현
- 람다 표현식은 이런 인스턴스를 생성하는 아주 편리한 문법 제공(문법이라고 이해하면 되나?)
#### 람다 표현식 문법
- 구현부 : 표현식을 여러 줄로 작성할 때는 메서드를 작성하는 것처럼 작성
- {} 감싸고 명시적인 return 문 사용
	```java
	(String first, String second) -> {
		int difference = first.length() < second.length();
		if (difference < 0) return -1;
		else if (difference > 0) return 1;
		else return 0;
	}
	```
- 람다 표현식이 파라미터를 받지 않으면 파라미터가 없는 메서드처럼 빈 괄호 붙임
	```java
	Runnable task = () -> { for (int i = 0; i < 1000; i++) doWork(); }
	```

- 파라미터 타입을 추론할 수 있다면 파라미터 타입 생략
	```java
	Comparator<String> comp
		= (first, second) -> first.length() - second.length();
	```

- 메서드에서 추론 대상의 타입 파라미터를 한 개만 받으면 괄호도 생략
	```java
	EventHandler<ActionEvent> listener = event ->
		System.out.println("Oh noes");
	```

- 람다 표현식은 추상 메서드가 한 개만 표함된 인터페이스에만 사용 : 함수형 인터페이스
- 예제
	- String 배열을 정렬하는 Arrays.sort(String[], Comparator);
	- Arrays.sort(words, (first, second) -> first.length() - second.length()); // 람다 표현식 구현

## 메서드 참조와 생성자 참조
### 메서드 참조
- 다른 코드에 전달하려는 액션을 수행하는 메서드 : 이 메서드 참조용 특수 문법이 존재
- 예제
	- 대소문자 구분없이 문자열 정렬(람다 표현식)
		```java
		Arrays.sort(strings, (x, y) -> x.compareToIgnoreCase(y));
		```
	- 메서드 표현식으로 구현
		```java
		Arrays.sort(stirngs, String::compareToIgnoreCase());
		```
	- String::compareToIgnoreCase 는 람다 표현식 (x, y) -> x.compareToIgnoreCase(y) 에 대응하는 메서드 참조
- :: 연산자는 메서드 이름과 클래스를 분리
- 메서드 이름과 객체의 이름을 분리
	1.클래스::인스턴스메서드
	2.클래스::정적메서드
	3.객체::인스턴스메서드

### 생성자 참조
- 메서드의 이름이 new 인 점만 제외하면 메서드 참조와 같음
- Employee::new : Employee 생성자 참조
- 배열 타입 생성자 참조 : int[]::new 

## 람다 표현식 처리하기
- 람다를 사용하는 핵심 목적은 나중에 실행하기 위한 것
	- 별도의 스레드에서 코드 실행
	- 코드를 여러 번 실행
	- 알고리즘의 올바른 지점에서 코드 실행(정렬에서의 비교 연산 같은 경우)
	- 어떤 이벤트가 발생할 때 코드 실행
	- 필요할 때만 코드 실행
- 이해하기 위한 예제
	- 액션을 n번 반복하기 위해 repeat 메소드에 카운트와 액션 전달
	- 람다를 받으려면 함수형 인터페이스를 선택, 구현해야 함. Runnable사용
		```java
		public static void repeat(int n, Runnable action) {
			for ( int i = 0; i < n; i++) action.run();
		}
		```
	- 람다 표현식의 구현부는 action.run()이 호출될 때 실행됨.
- 함수형 프로그래밍 언어 대부분은 함수 타입이 구조적. 자바는 명확히 함수형 프로그래밍 언어라고 하기에는 부족(객체 지향 언어라고)
- 자바에서는 Comparator<String>과 같은 함수형 인터페이스로 함수의 의도를 선언: 이를 프로그래밍 언어 이론에서 명목적 타입 지정 이라 함 -> 자바에서 함수형 인터페이스를 사용해서 람다를 표현한다
- 자주 사용하는 함수형 인터페이스

| **함수형 인터페이스**  | **파라미터 타입**  | **반환타입**  | **추상 메서드 이름**  | **설명** | **다른 메서드** |
| -------------- | ----------- | ------ | ------------- | -- | --------- |
|Runnable|없음|void|run|인자나 반환 값 없이 액션을 수행||
|Supplier<T>|없음|T|get|T 타입 값을 공급||
|Consumer<T>|T|void|accept|T타입 값을 소비|andThen|
|BiConsumer<T,U>|T,U|void|accept|T와 U 타입 값을 소비한다.|andThen|
