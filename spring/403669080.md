## Spring Boot project 구조

- 일반적인 Project 구조
```java
project
 ┣━ src
 ┃  ┣━ main
 ┃  ┃  ┣━ java
 ┃  ┃  ┗━ resources
 ┃  ┃       ┣━ static
 ┃  ┃       ┣━ templates    
 ┃  ┃       ┗━ application.properties 
 ┃  ┣━ test
 ┃  ┃  ┗━ java
 ┣━ target
 ┣━ HELP.md
 ┣━ mvnw
 ┣━ mvnwcmd
 ┗━ pom.xml

```

- maven 이 제공하는 프로젝트 구조를 따름- src/main/resources 에 xml, 프로퍼치 파일 등록- src/main/resources 에 웹 어플리케이션 관현 static(정적인 웹 리소스)과 template 파일(템플릿 기반 웹리소스) 등록
	- application.properties or application.xml  프로젝트 전체 설정 및 프로퍼티 관리
	- pom.xml : 프로젝트 환경 설정 및 dependency 관리
## Spring Boot 웹 어플리케이션
- Spring Web Application 실행
	- main 클래스에 @SpringBootApplication 정의(default 설정이 web application 실행으로 됨)
```java
java
		@SpringBootApplication
		public class SpringDemoApplication {
			public static void main(String[] args) {
				SpringApplication.run(SpringDemoApplication.class, args);
			}
		}
```

- @SpringBootApplication 선언 필수
		- 현재 @SpringBootApplication 이 정의된 클래스 경로를 기준으로 설정, 컴포넌트 스캔 등이 진행됨
			- @Target(ElementType.TYPE)
			- @Retention(RetentionPolicy.RUNTIME)
			- @Documented
			- @Inherited
			- @SpringBootConfiguration
			- @EnableAutoConfiguration
			- @ComponentScan
		- base package 가 아닌 별도의 패키지를 스캔하고자 할 경우 @SpringBootApplication과 별개로 @ComponentScan(basePackages{}) 정의 필요


- Spring 구동 시 설정 변경
	- Spring Web Application 실행 여부
```java
java
		@SpringBootApplication
		public class SpringDemoApplication {
			public static void main(String[] args) {
				SpringApplication application =
				new SpringApplication(SpringDemoApplication.class);
				// WebApplicationType 변경(NONE|SERVLET|REACTIVE)
				application.setWebApplicationType(WebAplicationType.NONE);
				application.run(args);
			}
		}
```

- WebApplicationType
		- NONE : 자바 어플리케이션으로 실행
		- SERVLET : Spring MVC 기반 웹 어플리케이션 구동
		- REACTIVE : Spring Webflux 실행
	- properties에 WebApplicationType 설정
		- application.properties 에 web-application-type 항목에 설정
```properties
properties
			## WebApplicationType Setting (none|servlet|reactive)
			spring.main.web-application-type=none
```

- properties 설정이 java 설정보다 우선됨 (properties > java)

### 웹 어플리케이션 구현
#### @RestController
- REST 방식의 응답을 처리하는 컨트롤러 선언
- @RestController Controller method가 리턴한 데이터 자체를 클라이언트에 전달
	- 클라이언트에 전달되는 데이터는 대부분 문자열이거나 VO나 Collection 형태의 자바 객체
	- VO객체를 JSON 데이터로 변환하여 응답 바디에 출력
	- 자바 객체가 전달되는 경우에는 자동으로 JSON 으로 변환하여 처리

#### @Controller
- MVC 방식 응답을 처리하는 컨트롤러 선언

#### 웹 어플리케이션 구현 시 유용한 툴
##### Spring DevTools
- 코드 수정 시 애플리케이션 재시작 불필요
- maven이나 gradle에 spring-boot-devtools 추가
##### lombok 라이브러리
- VO 객체의 private field에 대한 접근자 자동 생성
	- lombok 제공 annotation
	  - @Getter
	  - @Setter
	  - @RequiredArgsConstructor
	  - @ToString
	  - @EqualsAndHashCode : equals(), hashCode() 메소드 생성
	  - @Data : @Getter, @Setter, @RequiredArgsConstructor, @ToString, @EqualsAndHashCode 모두 포함하여 생성

### Spring Boot 핵심 기능
#### Starter
- spring-boot-dependencies.. Spring Boot Starter, dependencies 정보 : property와 dependency 정보 상속
    - 각 dependency의 버전 및 depend-on 관리를 쉽게 해줌
    - spring-boot-parent… : plugin 관련 설정 상속

#### Autoconfiguration
- @SpringBootApplication에 포함된 @EnableAutoConfiguration 이 담당
- @ComponentScan은 @Configuration, @Repository, @Service, @Controller, @RestController가 붙은 객체를 메모리에 올림
- @EnableAutoConfiguration은 자동 설정과 관련된 어노테이션
	   - 객체가 동작하기 위한 설정 정보나 필요한 객체들을 메모리에 올림
	   - dependency 는 spring-boot-autoconfigure-.. 로 시작
	   - META-INF/spring.factories 파일을 참조하여 여러 가지 bean 생성(Spring Boot  특정 버전 이후로는 없음)
-  참고) 웹 애플리케이션에 관련된 WebMvcAutoConfiguration의 어노테이션 분석
	- @Configuration : Spring Bean 설정 클래스임을 의미
	- @ConditionalOnWebApplication : 웹 애플리케이션 타입이 어떻게 설정되었 있는지 확인. Type.SERVLET 설정시 활성화
	- @ConditionalOnClass: 특정 클래스가 클래스 패스에 존재할 때 현재 설정 클래스를 적용
```java
java
		@ConditionalOnClass({servlet.class, DispatcherServlet.class, WebMvcConfigurer.class})
```

- @ConditionalOnMissingBean: 특정 클래스 객체가 메모리에 없을 때 현재 설정 클래스를 적용
```java
java
		@ConditionalOnMissingBean(WebMvcConfigurationSupport.class)
```

- @AutoConfigureOrder: 자동 설정 클래스의 우선 순위를 지정
```java
java
		// 현재 자동 설정 클래스의 우선 수위를 가장 높은 우선 순위보다 10단계 높게 설정
			@AutoConfigureOrder(Ordered.HIGHEST_PRECEDENCE + 10)
```

- @AutoConfigureAfter: 현재의 자동 설정 클래스가 다른 자동 설정 클래스 다음에 적용되도록 지정
```java
java
		@AutoConfigureAfter({ DispatcherServletAutoConfiguration.class, TaskExecutionAutoConfiguration.class, ValidationAutoConfiguration.class})
```

- Spring boot 로그를 debug로 설정하면 auto configure 한 정보를 볼 수 있음
    - 자동설정에 추가하는 방법
      1.  자동 설정에 추가할 어플리케이션을 구현 (ex: JDBC Connection Manager 구현 등)
      2.  @Configuration 클래스 구현 - @Bean 메소드 구현(JDBC Connection Manager의 설정값 지정하여 bean 등록)
      3.  src/main/resources 에 META-INF/spring.factories 파일 생성
      4.  spring.factories 파일에 EnableAutoConfiguration 속성 값으로 @Configuration 클래스 등록
```properties
properties
    org.springframework.boot.autoconfigure.EnableAutoConfiguration=com.config.JDBCAutoConfiguration
```

### 자동설정 재정의
- @Configuration으로 정의한 클래스를 재정의
- 설정만 바뀌어서 재배포를 하면 메모리에 같은 타입의 빈이 중복 등록되어 충돌남
1.  앞에서 구현한 starter를 dependency 로 추가하는 프로젝트 구현
    - JDBC 등록하는 connectionManager의 설정값 변경 필요 - 자동 설정하는 DB 가 아닌 다른 DB 사용시
      1.  변경된 설정값을 적용하는 @Configuration 구현
```java
java
          @Configuration
          public class BoardConfiguration {
            @Bean
            public JDBCConnectionManager getJDBCConnectionManager() {
              JDBCConnectionManager manager = new JDBCConnectionManager();
              manager.setDriverClass("org.h2.Driver");
              manager.setUrl("jdbc:h2:tcp://localhost/~/test");
              maanger.setUsername("sa");
              manager.setPassword("");
              return manager;
            }
          }
```
2.  application.properties에 항목 추가 - starter에 있는 JDBCConnectonManager와 충돌남
          - **spring.main.allow-bean-definition-overriding=true**
          - 새로운 bean이 기존의 bean을 덮어쓰도록 함
	      1. 변경 후 재실행해도 이전 DB설정을 불러옴 -> **문제 해결**: @Conditional을 사용하여 조건에 따라 새로운 객체를 생성할지 말지 결정하도록 처리
	      2. 중요한 건 앞서 등록된 jar는 spring.factories 파일 내에 자동 설정으로 정의했기에 Spring Boot 실행 시, @ComponentScan 에서 재정의된 @Configuration 클래스를 읽어도 이후 진행되는 EnableAutoConfiguration이 실행되면서 자동 설정으로 등록된 이전 Bean 설정을 불러 들임 => 이전 설정을 계속 부르게 됨

      3.  starter의 @Configuration 구현 클래스에 @ConditionalOnMissingBean 추가 : 중복 Bean 등록 안 되게 처리(조건 분기하도록)
          - **@SpringBootApplication 실행 순서** : @ComponentScan 으로 패키지내 Bean 생성, 등록, @EnableAutoConfiguration 자동 설정에 의한 Bean 등록 =\> H2 DB가 아닌 Oracle DB가 등록됨
          - **@ConditionalOnMissingBean** 은 등록하려는 Bean이 메모리에 없는 경우에만 Bean 등록 =\> @ComponentScan 으로 H2 Db Connection Manager를 등록한 후에 @ConditinoalOnMissingBean annotation에 따라 @EnableAutoConfiguration 이 설정된 Bean Scan 안 함

# 독립 실행 가능 JAR
- Spring Boot는 독립적으로 실행 가능한 어플리케이션을 빠르게 개발하는 것을 목적
- WAR 대신 JAR 를 선호
- 다른 jar와 비교시 Spring Boot는 BOOT-INF 디렉토리를 가짐
- BOOT-INF 는 실제 application class와 library(톰캣 라이브러리도 포함)로 구성
- META-INF에 실행될 어플리케이션 정보 저장됨
  - Main-class, start-class, Spring-boot-class, spring-boot-lib 등
```yaml
yaml
    Main-Class: org.springframework.boot.loader.JarLauncher
    Start-Class: com.nettoall.ChapterApplication
    Spring-Boot-Classes: BOOT-INF/classes/
    Spring-Boot-Lib: BOOT-INF/lib/
    Created-By: Apache Maven 3.5.3
    Build-Jdk: 1.8.0)291-1-ojdkbuild
    Implementation-URL: https://projects.spring.io/Spring-boot/$/spring-boot-starter-parent/Chapter
```

- 패키징된 jar 파일 실행 : 일반 jar는 불가능함
  - 일반적으로 jar 내에 여러 jar 포함시 허용 안 되며, 원칙적으로는 여러 jar 안에 클래스를 풀어서 하나의 jar로 만들어야 함
  - 스프링 부트는 패키징된 JAR 파일 안에 있는 또 다른 JAR 파일을 읽어서 클래스들을 로딩하는 유틸리티 클래스 제공 (org.springframework.boot/loader/jar)
  - JarFile 로더 클래스가 BOOT-INF/lib 폴더에 있는 수 많은 JAR 파일을 사용할 수 있도록 로딩
